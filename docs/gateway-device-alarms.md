# 网关设备离线报警

中心监视已启用、已分配网关且有测点的设备。当前会话报告通信故障、采集结果过期，或者网关失联、租约过期、配置长时间未确认、设备状态长期缺失，都会进入离线判断。故障持续超过延时后生成一条设备报警；设备本身尚未投入采集时给予状态宽限。

## 状态与恢复证据

中心把设备状态、网关/会话/配置归属、源时间、接收时间及待报警起点保存在配置库 `GatewayDeviceHealth`。心跳只更新当前已确认配置的设备状态；当前会话和配置下的新鲜遥测也能提供通信证据，兼容没有设备状态字段的旧网关。新网关上送可选 `statusTs`，用于阻止晚到的旧状态覆盖新故障；旧网关使用中心接收时间判断。

新鲜采样阈值为 `max(3000 ms, 3 × 采集周期, 采集周期 + 设备超时)`。网关心跳声称在线时，最近采集时间必须满足该阈值。已保存的在线状态在有效租约内保留，最长不超过采样阈值与租约时长的较大值；后续心跳继续报告过期的采集结果会被判为故障。这样心跳间隔不会直接造成短周期设备反复报警，同时能发现采集任务停止更新。

- 恢复要求当前网关、当前会话、当前配置的新鲜通信证据。只有握手或配置确认，不足以恢复设备报警；来源时钟超过中心 1 秒的状态不能用于恢复，也不能阻塞后续正确状态。
- 旧会话、旧配置和过期补传可以按既有规则补历史质量，不能改变当前设备报警。一个变量返回 Bad 质量仍可能表明设备通信正常，变量质量与设备离线分别处理。
- 中心重启保留活动事件和未达到延时的故障起点，不通过结束旧事件来清理运行状态。连续故障复用同一事件 ID，恢复后再次故障生成新事件；已有确认人和确认时间保留。
- 网关停用、会话释放和密钥轮换会使仍启用的所属设备失去有效连接，按延时报警。设备停用、删除、清空测点或迁移则关闭旧事件，并记录具体结束原因；本地迁到网关时也关闭遗留的本地设备离线事件。

离线起点来自中心观察及租约判断，不能当作失联现场的精确故障时间。中心断网期间现场已发生并恢复的完整报警过程，目前不依据过期包补造当前事件；历史质量区间和更完整的事件归档仍按第 5、6 项推进。

## 配置与界面

| 配置项 | 默认值 | 范围及用途 |
|---|---|---|
| `Gateway:DeviceOfflineDelayMs` | 3000 | 0～300000 ms，连续故障达到此延时才报警 |
| `Gateway:DeviceStateGraceMs` | 15000 | 1000～300000 ms，首次监视和配置切换时等待状态的宽限；不结束已有活动报警 |
| `Gateway:LeaseSeconds` | 30 | 15～120 秒，网关失联判断及状态有效期的上限依据之一 |

监视器约每秒检查一次，实际发现时间还受心跳、采集周期和中心处理负载影响。状态及事件在事务中保存后推送 SignalR；推送失败不回滚或重复创建事件，重新查询页面可取得已保存结果。通知持久投递与运维告警不是本阶段交付范围。

“报警”页面显示采集位置，并在结束时间下方显示结束原因。真实通信恢复与配置性关闭分别记录；确认操作沿用管理员/操作员权限。`GET /api/alarms?activeOnly=true` 未显式指定时间范围时包含超过一天仍未结束的活动事件；历史查询保留默认一天窗口，显式起止时间继续生效。

远程控制也校验设备健康证据的会话、配置和新鲜度。网关本机刚恢复、中心尚未收到新鲜证据时，中心会拒绝新命令；操作端应等待中心状态更新，不自动重新下发未知命令。

本阶段验证包含持久事件去重及恢复、确认保留、中心重建、旧数据隔离、配置性关闭、实际租约到期的页面操作，以及独立 OPC 网关撤销信任/重新信任导致的故障与恢复。它不代表完整远程网关或第 3 项验收完成；网关管理界面、服务安装、逐协议实机、长稳、规模和故障演练继续按 [网关完整范围](remote-gateway.md) 推进。
