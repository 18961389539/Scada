# 配方管理

入口：左侧菜单“配方管理”（`/recipes`），接口前缀 `/api/recipes`。配方下发不另开写入通道，每个参数都经过《现场操作控制闭环》（`field-control.md`）中的 `ControlCommandService.SubmitAsync`。

## 概念

- **配方模板**（`RecipeTemplate`）属于一个区域，定义 1～200 个参数。每个参数包含：
  - 键（字母开头，最多 40 个字符），配方值按键对应；
  - 名称和单位；
  - 绑定的可写采集测点（同一模板内不能重复）；
  - 可选的下限、上限和默认值。
  
  模板可以勾选“整批双人复核”。
- **配方**（`Recipe`）是某个模板的一组参数值，在同一模板内按名称唯一。
- **版本**（`RecipeVersion`）：
  - 新建配方得到 v1，之后每次保存都生成新版本，旧版本不可修改。
  - 保存时必须带上当前版本号（乐观并发），版本号不一致返回 409。
  - 版本来源分三种：`manual`（编辑）、`upload`（现场上载）、`project`（工程导入或回滚）。

## 校验

保存配方时校验以下几点：

- 每个参数都有值；
- 没有多余或重复的键；
- 值在模板的上下限之内；
- 值能按测点的类型和量程编码。

从现场上载的值，如果超出模板上下限，仍按实际值保存并返回提示。下发时这样的值会被拦截。

## 比较与上载

- `GET /api/recipes/compare?left={id}&leftVersion=&right={id|live}&rightVersion=` 可以比较两个配方、同一配方的两个版本，或者配方与现场实时值（`right=live`）。结果逐参数列出左右两侧的值，并标出差异数。
- `POST /api/recipes/upload { templateId, recipeId?, name?, note? }` 读取各参数测点的当前实时值：
  - 不带 `recipeId` 时保存为新配方；
  - 带 `recipeId` 时保存为该配方的新版本；
  - 任一参数没有有效值（质量不好或无数据）时整体拒绝，并列出缺失的参数。

## 下发流程

1. **预检查**（`POST /{id}/check`）：对每个参数执行控制闭环的完整检查，包括主备角色、就地/远程、挂牌、测点量程与编码、控制策略限幅、单次变化率、许可/互锁。另外再加配方模板的上下限检查。确认框会逐参数展示当前值、目标值和拒绝原因。
2. **整体判定**：只要有一个参数不通过，整批都不下发，记录为 `Rejected`（未下发任何参数）。界面上的确认按钮此时不可用。
3. **确认**：接口必须携带 `confirmed=true`。
4. **整批双人复核**：模板勾选了复核，或任一参数测点的控制策略要求双人复核时，整批生成一条复核请求（`ControlRequest.Kind = recipe`），在“现场操作 → 待复核”中处理。
   - 必须由另一位对模板区域和全部参数测点都有 Control 权限的用户批准，本人只能撤回。
   - 驳回、撤回或超时（300 秒）后记为 `Rejected`，不写任何参数。
   - 批准后写入时，按已复核处理，参数测点自身的复核要求视为已满足。
5. **写入前复查**：复核等待期间现场可能已经变化，所以开始写入前会对全部参数再整体检查一次。任一项不通过时一个都不写（`Failed`，“下发前复查未通过”）。
6. **逐个写入**：按模板参数顺序串行执行。每个参数先由控制闭环完成同点回读（比对编码后的原始值）；有独立反馈的，还要等待反馈。之后再按工程值核对回读值，容差为半个原始量化单位。
7. **失败即停**：任一参数失败、结果未知或回读不一致时立即停止，后面的参数记为“未写”（`skipped`）。
   - 如果已经有参数写入（或结果未知），状态记为 **`PartiallyApplied`（部分下发）**。消息里列出已写入的参数及原值→目标值、结果未知的参数和未写入的数量，并注明“现场处于新旧配方混合状态，请核对后处理（不会自动重发或回退）”。
   - 没有写入任何参数时记为 `Failed`。
   - 不自动重发，也不自动回退。自动回退同样是一次未经确认的现场写入，可能在故障状态下造成二次风险，应由操作员判断后重新下发旧版本，或单独处理。
8. **中止**：`POST /downloads/{id}/abort`，在当前参数写完后停止，状态为部分下发或中止。
9. **服务重启**：
   - 正常停止时，正在进行的下发会被打断。
   - 进程异常退出遗留的 `Running` 记录，在下次启动时标为部分下发或失败，消息含“服务重启，配方下发中断（不会自动续发）”，并写审计。
   - 下发**从不自动续发**。
10. **并发**：同一模板同一时刻只允许一个下发在执行。批准时如果另一配方正在下发，则本次记为失败（未写），需要重新发起。

## 审计

- 模板和配方的增删改都写差分审计，包括修改前后的参数值和版本号。
- 每个参数的写入都留有控制写入审计：来源为 `Recipe`，并记录配方名、版本和参数名。
- 下发的开始、拒绝、复核、结束和中断都写入操作日志（`TargetType = RecipeDownload`）。

## 权限

| 操作 | 需要 |
|---|---|
| 查看模板、配方、版本、比较、下发记录 | 模板区域 View |
| 新建/修改/删除模板 | 模板区域 Configure，且全部参数测点所在区域 Configure |
| 新建/修改/删除配方、上载 | 模板区域 Configure（上载另需参数测点 View） |
| 预检查、下发、中止 | 模板区域 Control，且全部参数测点所在区域 Control |
| 批准/驳回整批下发 | 同上，且不是申请人 |

## 工程包与快照

- 工程包新增分区 `recipeTemplates`，键为模板名称。
- 包内参数的测点写为 `tagRef`，模板下的配方（`recipes`：名称、说明、当前版本值 `values: [{key, value}]`）一并入包，因此也进入版本快照、差异比较和回滚。
- 导入或回滚时：
  - 包中配方的值与当前版本不同的，追加一个新版本（来源 `project`），历史版本保留；
  - 模板以包为准，包中没有的配方会被删除，但下发记录保留。
- 有正在下发或待复核的模板不能被导入、回滚修改或删除。
- 版本历史和下发记录属于运行记录，不入包。

## 已知限制

- 不支持配方参数之间的联动或公式（例如由 A、B 派生 C），也没有按批次和工单的配方调度。
- 下发顺序固定为模板参数顺序。需要特定写入时序或握手（例如先写参数、再写“装载”位）的，可以用顺控实现。
- 回读核对依赖设备回读值。对于写后被 PLC 立即改写的参数（例如 PLC 侧有限幅），会判为不一致并停止。
- 尚未在真实 PLC 上做大配方（上百参数）的耗时和部分失败演练。
