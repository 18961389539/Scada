## 2. P0——高频路径上的硬摩擦

### P0-1 报警页没有任何键盘操作（✅ 已落地）

**现象**：报警确认、写备注、暂挂、看时间线、翻页全部依赖鼠标点击；表格行无法用键盘选中。

**证据**
- `views/AlarmsView.vue` 全文件无 `@keydown` / `tabindex` 行级处理；表格仅在 `el-table-column type="selection"` 下有复选框。
- 全局只注册了一个快捷键：`layout/AppLayout.vue:347-353`（Ctrl/⌘+K 打开命令面板）。

**影响**：报警洪峰时操作员要处理几十条，鼠标点击 + 移动 + 二次确认的路径过长；ISA-101 / WinCC / Ignition 一类 HMI 的通行约定是 ↑↓ 选行、A 确认、空格勾选、Enter 打开详情。现场戴手套或用触控板时差距更明显。

**建议改法**（不引入新依赖）
1. 给 `el-table` 加 `highlight-current-row` + `ref.scrollToRow`，维护 `activeRowIndex`；`↑/↓` 移动、`Space` 切换该行勾选、`Enter` 打开时间线。
2. `A` 对当前行发起确认（复用 `openAck`），`Shift+A` 对已勾选批量确认（复用 `batchAck`）。
3. 快捷键仅在焦点不在输入框/下拉内生效，且页面处于 `tab === 'live'`。
4. 表格下方加一行极简提示（`A 确认 · Enter 详情`），可复用 `.alarm-scroll-hint` 样式位。

**工作量**：中（约 120 行，集中在 `AlarmsView.vue`，可抽 `composables/useRowKeyboard.ts` 供 ControlView 复用）。

**落地**（第六轮）

键位按 HMI 惯例确定，**所有按键只负责「进入已有流程」**，不绕过确认框：

| 按键 | 行为 |
|---|---|
| `↑` / `K`、`↓` / `J` | 上下移动行聚焦 |
| `Home` / `End` | 首行 / 末行 |
| `A` | 对聚焦行打开确认弹窗（未确认且有权限时） |
| `N` | 打开备注弹窗 |
| `T` / `Enter` | 打开该报警时间线 |
| `X` / `Space` | 勾选 / 取消勾选，用于批量确认（仅实时页） |
| `/` | 跳到搜索框 |
| `Esc` | 解除行聚焦 |
| `?` | 打开快捷键一览 |

实现要点：

- **聚焦用 `id` 锚定而不是行号**。30s 轮询会重排列表，行号会漂；`focusedId` + `focusedIndex` 计算属性让聚焦跟着那条报警走，行被刷新掉（确认后转历史、过滤变化）时自动释放。
- **焦点提示不用 `outline`**：表格行会裁掉描边，改用左侧 3px 主色条 + `--scada-primary-soft` 底色，与 Critical 行的红底语义不冲突（聚焦规则声明在后，优先级更高）。
- **三处防误伤**：输入框/下拉内不触发（`isTypingTarget`）；任一弹层打开时不触发（`overlayOpen`，含 MessageBox）；用 Tab 走到按钮/链接上时 `Enter`/`Space` 交还浏览器原生激活（`onInteractiveElement`）。
- 移动端（≤768px）不启用：桌面表格已隐藏，行聚焦不可见，键盘流程没有意义。
- 提示分两处：列表摘要行右侧常驻「↑↓ 选择 · A 确认 · T 时间线 · ? 全部快捷键」，工具栏给一个 `?` 按钮（`data-test="alarm-kbd-help"`），移动端两者都隐藏。

### P0-2 监视/分析页的视图状态不进 URL，刷新即丢、也没法交接（✅ 已落地）

**现象**：报警页选了「Critical + 关键词 + 第 3 页」，趋势页选了 5 个测点 + 8 小时区间，刷新或分享链接后全部回到默认。

**证据**
- `AlarmsView.vue:381-384`：只**读** `route.query.state`，用户点击状态筛选（`:11-27`）时不写回 URL；`levelFilter`/`categoryFilter`/`keyword`/`livePage` 完全不进 URL。
- `TrendsView.vue:527-546`：只**读** `route.query.tagId`；`selectedTags`、时间范围、自动刷新开关均不写回。结果是从报警页跳过来的单测点视图无法扩展成可分享的多测点视图。
- 对照组：`composables/useCatalogQuery.ts:17-29` 已经把筛选 + 页码写回 URL，`DevicesView.vue:17-33`、`TagsView.vue:5-11` 都在用。

**影响**
1. F5 后丢失上下文（现场排查时很常见）。
2. 班组交接只能用口头描述「你点报警页，然后选 Critical」，无法发链接。
3. 同一套产品里两种交互口径，用户学两遍。

**建议改法**：把 `useCatalogQuery` 推广到 `AlarmsView`（`state/level/category/keyword/page`）与 `TrendsView`（`tagIds` 逗号分隔、`from/to`、`preset`）。`useCatalogQuery` 当前只处理 `Record<string,string>`，需要扩一个 `syncArray` 变体或让 Trends 自己做 `router.replace`（注意用 `replace` 而非 `push`，避免污染历史栈）。

**工作量**：小-中（每页 30-50 行）。

### P0-3 权限不足与无效地址都是"静默跳走"（✅ 已落地）

**现象**：用户点开别人发的链接，或者地址栏打错，页面悄悄变成总览页，没有任何说明。

**证据**
- `router/index.ts:112-114`：策略不通过直接 `return defaultLandingPath(auth.user)`，无提示、无 toast。
- `router/index.ts:83`：`{ path: '/:pathMatch(.*)*', redirect: '/' }`，未知路径吞掉后同样落到总览。

**影响**：最常见的现场投诉形态是"我这个页面打不开/不见了"。运维和班组长无法自助判断是"没权限"还是"链接过期"，只能找管理员。

**建议改法**
1. 未知路径改为一个轻量 404 页（`views/NotFoundView.vue`），给出「返回总览 / 打开命令面板」两个出口。
2. 策略不通过时 `router.replace({ path: landing, query: { denied: to.fullPath } })`，`AppLayout` 读到 `denied` 后弹一次 `ElMessage.warning`（一次性，读取后清掉 query），文案带上目标页标题。

**工作量**：小（约 60 行，新增 1 个 view + AppLayout 挂一个 watcher）。

## 3. P1——明确影响效率或一致性

### P1-1 报警页在移动端没有卡片降级，7 列表格硬塞进手机（✅ 已落地）

**证据**：`AlarmsView.vue:991-995` 在 `max-width: 768px` 下只把 `.alarm-table-wrap` 高度限制成 `clamp(280px, 50vh, 520px)`，仍然渲染 `el-table`（`:125-206`，含状态/等级/类别三枚标签、来源、值、起止时间、确认人、5 个行内按钮）。
**对照**：`OverviewView.vue:91-128`、`RealtimeView.vue:85-95` 都有专门的 `.mobile-list` 卡片布局。
**建议**：照 Overview 的 `mobile-list` 结构补一版报警卡片（等级色条 + 消息 + 来源 + 持续时长 + 「确认」主按钮），桌面表格保持不动。这是报警页在手机/平板上可用的前提。
**工作量**：中（约 100 行模板 + 复用现有样式类）。

### P1-2 活动报警的「已持续」不会走动

**证据**：`AlarmsView.vue:534-540` 的 `duration()` 用 `Date.now()` 计算，但页面没有引入 `useNowTicker`；只有推送或 30s 轮询（`:860`）触发重渲染时才更新。
**对照**：`RealtimeView.vue:151,173`、`SetupGuide.vue:41,54` 都用了 `useNowTicker`；`ControlView.vue:302` 用自己的 `now` ref 驱动倒计时。
**影响**：报警持续时长是判断严重程度的核心依据，停着不动会让人误判「刚发生」或「已经很久」。
**建议**：引入 `useNowTicker()`，`duration()` 读 `now.value`。1 行 import + 1 行改动。
**工作量**：极小。

### P1-3 趋势选点器撑不住大点数站点（✅ 已落地）

**证据**：`TrendsView.vue:5-18` 是单个 `el-select multiple filterable`，选项是**全量** `tags`，硬上限 `:multiple-limit="50"`，标签文案 `设备名 / 测点名` 在渲染时才拼。
**影响**：几千点位的站点打开下拉会明显卡顿；用户找点只能靠记名字；常用组合每次重选；50 上限是硬编码，超了静默拒绝。
**建议**（分两步，先做 1）
1. 加「最近使用测点」（`localStorage` 按用户存最近 10 个 tagId，复用 `nav/favorites.ts` 的写法），下拉顶部固定展示。
2. 若点位规模确实上千：改成按设备分组的 `el-option-group`，或做远程搜索（`filter-method` + 分页取 tag）。
**工作量**：第 1 步小（约 40 行）；第 2 步中。

**落地**（第六轮 ＋ 第七轮）

第 1 步（最近使用）见第 8 节。第 2 步没有走「远程搜索」，理由如下：

- 后端 `GET /api/tags?search=` 支持关键词，但**没有分页上限**——搜一个常见字仍然会把全量结果一次性返回，远程搜索拿不到「只取前 N 条」的能力，网络开销和现在一样。
- 真正卡的是**渲染**：`el-select` 会为每个 `el-option` 建 DOM 节点，几千条展开就掉帧；数据本身（几千条 `Tag`）在内存里并不慢。
- 因此改用 `el-select-v2`（虚拟列表）：只绘制可见的十几行，`filterable`、`collapse-tags`、`multiple-limit` 行为不变，分组结构保持「最近使用 / 全部测点」。

改动细节：

- `options` 改为分组数组（`[{ label, options: [{ value, label }] }]`），标签在 computed 里一次拼好，并用设备名 Map 代替逐条 `find`，避免展开下拉时反复计算。
- `el-select-v2` 的 `filterOptions` 会**丢弃没有命中的整组**，所以搜索时不会留下空分组。
- 选中项的标签靠内部 `allOptionsValueMap` 从全量选项回查，刷新、粘贴链接后仍能显示设备名 / 测点名，不会退化成 `#123`。
- 达到 50 个上限时选项自动置灰（v2 的 `multipleLimit` 语义），旁边给出「已达 50 个测点上限，先移除再添加」——原来是静默拒绝。
- 样式核对：`el-vl__window` / `el-vl__wrapper` 已随组件进入构建产物，虚拟列表不是「无样式」状态。

未做：真正的服务端分页取点。需要后端给 `/api/tags` 加 `skip/take` 与总数返回，属于接口契约变更，不塞进易用性这一轮。

### P1-4 趋势页日期控件写死 360px，小屏溢出

**证据**：`TrendsView.vue:31-38` 内联 `style="width: 360px"`。
**对照**：`AlarmsView.vue:938` 的处理是 `flex: 0 1 390px; width: 390px; min-width: 240px; max-width: 100%`，并在 `:1002-1009` 为移动端重排了日期面板。
**建议**：把内联样式换成 class，套用 AlarmsView 的响应式尺寸 + 移动端 popper 规则（可直接复制 `alarm-date-popper` 那段，考虑提成全局 `.scada-date-popper`）。
**工作量**：小。

### P1-5 帮助文档只能搜当前页，33 篇无法跨页检索（✅ 已落地）

**证据**：`PageHelpButton.vue:99-113` 只按当前路由加载一个 key 的内容；`:140-177` 的搜索只在该页 `bodyLines` 上做。
**影响**：用户知道"有个设置要改"但不知道在哪个页面时，帮助系统帮不上忙——这正是帮助系统最该发挥作用的时刻。命令面板搜的是页面标题，不是帮助正文。
**建议**：帮助抽屉加一个「搜索全部帮助」开关：加载整份 `help/zh.json`（本地 JSON，体积可接受），跨 key 检索并列出「页面标题 + 命中行」，点击跳转该页并自动打开其帮助。
**工作量**：中（约 80 行）。

### P1-6 命令面板无"最近访问"，35 个页面里找路靠背（✅ 已落地）

**证据**：`CommandPalette.vue:114-137` 分组只有「收藏」和「全部页面」；`nav/favorites.ts` 只有 `loadFavorites/toggleFavorite`，没有访问记录。
**影响**：收藏是主动动作，多数人不会用；「最近访问」是被动、零成本的，对页面多的产品收益更高。
**建议**：`AppLayout` 的 `afterEach` 里记录最近 8 条到 `localStorage`（按用户名），命令面板空查询时插到「收藏」后面。约 20 行。
**工作量**：小。

## 6. 复验清单（沙箱恢复后执行）

1. `npm run build`（含 `vue-tsc`）——确认无类型回归。
2. `npm run i18n:check`——新增文案必须同时进 `zh-CN.ts` / `en-US.ts`。
3. `npm run check:access`——若改路由策略提示，需回归权限用例。
4. `npm run test:smoke -- --repeat-each=3`——重点覆盖 `alarms`、`trends`、`realtime` 三页。
5. 手工：报警页刷 URL 往返、趋势页多测点复制链接给另一账号、无权限账号访问 `/system`、手机宽度 375px 下报警列表。

## 7. 不建议做的

- **不要**给所有表格加虚拟滚动来"提升易用性"——当前分页 100 条已足够，收益低、回归面大。
- **不要**重做导航结构。`nav/catalog.ts` 单一数据源、命令面板与侧栏共用，是目前最健康的部分。
- **不要**为移动端单独做一套交互流程。现有"桌面表格 + 移动卡片"的分叉模式已经够用，报警页补齐即可。

第一轮审计集中在监控路径（总览 → 实时 → 报警 → 趋势）。这轮转看配置页，方法是先按「表单弹窗有没有未保存守卫」扫一遍，再看守卫是否真的绑到弹窗上——结果发现「创建了但没绑定」这一类问题。

| 发现 | 证据 | 影响 | 处理 |
| --- | --- | --- | --- |
| 守卫创建了但没绑定 | `OeeConfigView.vue` 创建 7 个 `useEditDialog`，全文件只有 1 处 `before-close`；源码注释自认「当前尚未绑定」 | 编辑产线 / 产品 / 班次 / 原因 / 停机 / 修正 / 阈值时，按 Esc 或点 X 静默丢弃改动 | 7 个弹窗全部绑定 `:before-close` + `@keydown`（Ctrl+Enter 保存） |
| 批量建点无守卫 | `TagsView.vue` 的 `batchVisible` 弹窗有 10 个参数 + 可逐行改名，却没接 `useEditDialog` | 配好几十行点位名后误按 Esc 全部丢失 | 新增 `batchGuard` 并绑定 |
| 四元组建规则无守卫 | `AlarmRulesView.vue` 的 `quadVisible` 同样只设了 `close-on-press-escape` | 四条阈值改到一半丢失 | 新增 `quadGuard` 并绑定 |

三个实现细节（改动时别踩回去）：

1. **守卫基线是同步快照**：`useEditDialog` 在 `visible` 变 true 的那一刻记录基线。凡是「开窗后异步回填表单」的流程，必须先把回填做完再置 `visible`，否则一开窗就被判成已修改（`AlarmRulesView.openQuad` 原来就是先开窗再按量程回填，已调换顺序）。
2. **保存成功后直接 `visible = false`**：这会绕过 `before-close`，正是想要的——保存成功不该再问「要丢弃吗」。
3. **取消按钮走 `guard.close()`**：其他页面（`DevicesView` 等）早就是这个写法。直接 `visible = false` 会让「取消」变成不告而别的丢弃入口，与 Esc 的行为不一致。

- **找回原生滚动条**：Element 用 `scrollbar-width: none` 隐藏了原生滚动条。
  覆盖成 `thin` 会让 Chromium 忽略 `::-webkit-scrollbar`，而 `thin` 在 Windows 11 Edge 上
  是悬浮条（不占位、不动就不出现）；覆盖成 `auto` 后实测仍是 0 像素占位。换浏览器内核
  才能稳定，不可控。

### 表单保存失败：已经很扎实，不用改

对测点、设备两个最高频的表单做了故障注入（服务端 500 / 请求直接断网），逐项检查：

| 检查 | 结果 |
| --- | --- |
| 失败后弹窗是否保留 | 保留 |
| 失败后已填内容是否还在 | 在 |
| 是否给出可读错误 | 是（服务端 message 原样透传；断网显示「网络连接失败…」） |
| 恢复后能否原地重试 | 能，不必关窗重填 |
| 是否有未捕获异常 | 无 |

15 项检查全通过（3 个场景 × 5 项）。批量操作另有 `runBatch` / `reportBatch`
逐个记录失败项，也不会把部分失败说成成功。

### 控制命令失败：措辞会误导操作员

真正的问题在现场动作上。`errorMessage()` 对超时和断网的兜底是
「请求超时，服务可能繁忙，**请稍后重试**」——保存配置这样提示没问题，
但控制命令可能**已经写进 PLC 了，只是回执没回来**。操作员照着「请稍后重试」做，
就会把同一条命令重复下发一次。

现场处置和保存配置的判断依据完全不同，前端必须区分三种情形：

| 情形 | 现场状态 | 该说什么 |
| --- | --- | --- |
| 服务端返回错误码（4xx/5xx 带 message） | 命令被拒绝，**没有生效** | 原样展示拒绝原因，可以直接改条件重试 |
| 预检查没通过 | 命令**还没下发** | 明确说「未下发」，操作员才敢重试 |
| 超时 / 断网 / 连接重置（无响应） | **不知道有没有生效** | 「结果未知，先核对现场状态再决定是否重发」 |

改动：

- `api/http.ts` 新增 `commandErrorMessage()`：有 `response` 才走原来的 `errorMessage`，
  没有响应一律返回「结果未知」措辞。
- `RealtimeView` 写值：预检查失败改为「预检查没有完成，命令未下发：…」；
  下发失败改用 `commandErrorMessage`。
- `ControlView` 新增本地 `guardCommand()`，替换 6 处**真正动现场**的动作：
  启动顺控、中止顺控、挂牌、摘牌、切换就地/远程、**审批控制请求**（批准即下发）。
  配置类动作（保存测点、保存顺控定义等）仍用原 `guard`，因为它们失败时确实只是「没保存成功」。
- `composables/useActionError.ts` 同步提供 `guardCommand`，供其他页面使用。

### 一个没改的发现

写值弹窗里，第一次下发后命令编号就固定，输入框随之禁用——被服务端拒绝后
想改个值必须关窗重开。看着别扭，但这是刻意的：同一编号必须对应同一个目标值，
否则回执就失去意义。弹窗里已有提示「本次操作保留原命令编号；新的操作请重新打开对话框」。
保持现状。

## 13. 顺控执行到一半失败（第十二轮）

上一轮把控制命令的失败措辞理清了，但「命令下发之后」还有一段没走：顺控跑到第 3 步失败，
前 2 步已经把设备动了。这时操作员要判断三件事——**失败在哪一步、为什么、现场已经被动到哪一步**。
实际跑一遍，这三个问题在一个地方都答不上来。

### 发现

用一次「6 步、第 3 步失败」的运行做样本，逐屏看：

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 打开「流程图」看不到失败原因 | 弹窗里只有节点图和 `describeStep` 描述；`run.steps[].message` 完全没渲染。失败原因只出现在运行列表那一列的 `tiny muted` 里，列宽 320px |
| 2 | 没有「现场动到哪一步」的判断依据 | 节点只按状态上色（绿/红/灰），没有「已完成 2 步 / 未执行 3 步」的量化信息；而这两类步骤的处理方式完全不同——已执行的可能需要人工复位，未执行的直接没有动作 |
| 3 | 失败后想重跑，得滚回上面的顺控表再找 | 后端备注写的是「请核对现场状态后重新执行」，但运行行只有「流程图」和「中止」两个动作 |
| 4 | 别人启动的顺控，本页永远看不到 | 运行轮询的条件是 `runs.some(status === 'Running')`——本地没有 Running 就不发请求。别人启动的运行（或本页打开后才开始的）根本不会进入视野，失败也不会冒出来 |

第 4 条实际测了一遍：页面停在顺控页，把服务端运行列表从空改成一条 Running，等 6 秒，
表格仍是 0 行、`/api/control/runs` 只被请求过 1 次（就是首屏那次）。

### 改动

- **运行详情补齐摘要块**：失败/中止时在流程图上方给出「失败步骤 + 原因 + 已完成步骤 + 未执行步骤 + 下一步建议」。
  建议文案按状态分开：失败强调「已执行步骤对应的设备可能已被改变，且不会自动回退」；中止强调「中止不会回退已执行步骤」。
  两者都不建议直接重跑。
- **运行行与弹窗加「重新执行」**：只在失败/中止、且顺控定义还在、且有该区域控制权限时出现。
  点击走的仍是「执行」的确认框（列出**当前**定义），不新增快速通道；定义在本次运行后被改过时，弹窗里原有的「按当前定义显示」提示同时生效。
- **顺控页的轮询补上低频刷新**：停在顺控页时即使本地没有 Running，也每 5 秒查一次；运行中仍保持 1 秒。
  这是唯一能发现「别人启动的运行」的通道——系统目前没有运行状态的推送事件（SignalR 只推 `values` 和 `alarm`）。
- **弹窗打开后定位**：失败运行直接 `setCenter` 到出错那一步并保持 100% 缩放；其余情况做「有下限的整览」(`minZoom 0.8`)。
  为什么不干脆整览：6 步的链路在 440px 画布里整览只有约 0.5 倍，节点文字小到读不出来，而「适应」按钮随时可以手动整览。

### 两个实现细节

1. `el-dialog` 的内容在打开动画结束前尺寸为 0，组件内 `nodes-initialized` 触发的那次 `fit()` 会落空。
   改用对话框的 `@opened` 回调，动画结束后再定位/适配。
2. `SequenceFlow.fit()` 原来不接受参数，扩成可选参数（`padding` / `minZoom` / `maxZoom`），默认行为不变，
   设计器与既有调用方不受影响。

## 14. 批量操作可以中途停止（第十三轮）

上一轮结尾我提的「批量回执缺失败清单」是错的——`el-alert` 早就逐条列出了
`#id 消息：错误` 并给了重试按钮。于是换了个方向：**批量执行过程中**是什么状态。

### 发现

用 12 条报警、每条 ack 延迟 500ms 跑一次批量确认，在跑到第 3 条时检查页面：

| 观察项 | 结果 |
| --- | --- |
| 进度提示 | `确认中 3/12 · #102 出口压力高高限 3`（有，且够用） |
| 被禁用的按钮 | **62 个**——工具栏、每一行的「确认/备注/暂挂/记录」、分页器全部锁死 |
| 可用的「停止/取消」 | **没有** |

报警洪峰时全选 200 条、服务端每条 300~500ms，就是几十秒到两分钟完全不响应。
这期间要是来了新的 Critical 报警，操作员除了关掉页面没有别的办法。

### 改动

- `runBatch` 增加可选的第 5 个参数 `shouldStop`：每项开始前问一次，返回 true 就停下，
  已处理的结果照常返回，`BatchReport` 多一个 `canceled` 字段。四个已有调用方一行不用改。
- 报警页在批量确认进行中显示「停止」按钮；点击后按钮立即禁用，进度行改为
  「正在停止…（等待当前这条返回）」——单条请求已经发出去了，只能等它回来，不能假装立刻停。
- 结果提示补一行「已停止：还有 N 条未确认，可重新勾选后再确认」，并把提示条从
  绿色 success 改成中性 info——**停止不等于成功**，绿色会让人以为整批都处理完了。
- 停止后不弹「全部成功」的 toast（原来的判断只看有没有失败）。

### 没做的

`TagsView` 批量删除/归档、`DevicesView` 批量启停、`AlarmRulesView` 批量启停/删除
同样是「锁死且不能停止」，`shouldStop` 已经可用，但没接线。理由：这些是配置动作，
单条请求快、批量规模也小（几十条），且不像报警那样有时间敏感性。真要接，各页加一个按钮即可。

## 15. 慢网与触控（第十四轮）

这轮换了两个之前没测过的物理条件：**慢网络**和**触摸屏**。

### 慢网络：三条都合格，不改

给全部接口注入 900ms 延迟，检查最容易被慢网放大的三个行为：

| 检查 | 结果 |
| --- | --- |
| 首屏加载有没有明确加载态 | 有 loading 遮罩，不是空白表格 |
| 关键字输入是否防抖 | 连打 5 个字符只发 **1 次**带关键字的查询 |
| 切页签时是否残留旧数据冒充新结果 | 切到历史页后立即清空并显示加载态，无残留 |
| 保存按钮连点两次是否发出两个 PUT | 只发 **1 次** |

这几项都是以前踩过坑才补上的（防抖计时器、`loading` 闸门、`saving` 闸门），这次确认没有退化。

### 触摸屏：真正的问题是「点不中」

现场大量使用 1024×768 的触摸一体机和壁挂屏。在 `hasTouch` 环境下逐个量可交互元素：

| 页面 | 小于 28px 的目标 | 具体是什么 |
| --- | --- | --- |
| 报警 | 13 | 行选择框 **12×12**（含表头全选）、行内「趋势」链接 26×23 |
| 实时监视 | 6 | 行内「查看趋势」链接 52×**16** |

12×12 是鼠标尺寸。**批量确认的第一步就是勾选报警**——在触摸屏上手指落在 12px 方框里几乎不可能，
点歪了就是「没反应」。文字链接同理，只有一行高。

改动（全部包在媒体查询里，桌面零影响）：

- `@media (pointer: coarse)` 下把表格行选择框的可点范围撑到约 36px：
  用 `padding: 12px` 扩大命中区，再用 `margin: -12px` 抵消布局位移，方框视觉尺寸仍是 12px。
- 同一媒体查询下，表格内的文字链接（「趋势」「查看趋势」）改为 `inline-flex` + `min-height: 32px`，
  左右用负 margin 抵消内边距，文字位置不移动。
- 报警卡片（≤768px 的移动布局）里的同一个链接也一并覆盖——它不在表格里。

验证方式不是「量尺寸」而是「真点」：用元素内相对坐标点复选框扩出来的边缘（x=3），
Playwright 会校验该点确实命中该元素，被遮挡会直接失败；点完断言批量确认按钮变成「(1)」。

**顺带记录一个权衡**：触控下行高从 59px 涨到 68px（链接从 23px 撑到 32px 带来的）。
在 768 高的屏幕上少显示不到半行，换手指能点中，值得。

## 16. 把停止按钮铺开 + 新建弹窗兜底（第十五轮）

### 批量停止：上一轮只做了报警页，另外三个台账页没有

第十三轮给报警批量确认加「停止」时，`runBatch()` 已经带了 `shouldStop` 参数，但只有报警页真的传了。
测点、设备、报警规则三个页面还在用四参数版本——同样是逐条串行、同样可能勾错几百条，却只能干等或关页面。

这轮把三处接上，行为与报警页一致：

| 页面 | 入口 | 停止后 |
| --- | --- | --- |
| 测点 `/config/tags` | 批量删除、批量归档 | 不再下发，提示「已停止：完成 3/12 条，还有 9 条未处理」 |
| 设备 `/config/devices` | 批量启用、批量停用、批量删除 | 同上 |
| 报警规则 `/config/rules` | 批量启用、批量停用、批量删除 | 同上 |

几个细节：

- **停止按钮只在跑的时候出现**，和批量按钮同一排。跑完立刻消失，不会留一个点了没反应的按钮。
- **进行中的提示换成「正在停止…（等待当前这条返回）」**。逐条串行意味着已经发出去的那一条收不回来，
  不写这句的话，点了停止后界面还会停一两秒，操作员会以为没点上而反复点。
- **停止不算失败**。用 info 色提示而不是红色错误框，因为前面的条目确实成功了；
  有失败条目时仍走原来的黄色/红色汇总弹窗，并在末尾补一句还剩多少条。
- 文案抽到公共的 `batchUx` 段（`stopBatch` / `stopping` / `stoppedOnly` / `stoppedSuffix`），
  不再每个页面抄一遍。

### 新建弹窗：填了一半被 Esc 吃掉

`useEditDialog` 的未保存守卫在编辑类弹窗上已经铺开，但两个**新建**弹窗漏了：

| 弹窗 | 丢什么 | 处理 |
| --- | --- | --- |
| 外部接口 → 建 Key | 名称、4 个权限勾选、区域多选、限流值、备注 | 绑定 `beforeClose` + 取消按钮走 `guard.close()` |
| 对象模板 → 批量实例化 | 版本、设备、前缀、起始号、数量、基地址、步长（往往还要先看一遍预览表） | 同上 |

顺手修掉一个连带问题：这两个弹窗**从来没重置过表单**。上次填了一半关掉，再打开还是那些值——
看起来像是"已经建好了"。现在打开时先恢复默认值：

- 建 Key：名称清空、权限回到只勾 `ReadTags`、区域清空、限流回到 120。
- 批量实例化：前缀回到模板默认前缀、起始 1、数量 1、基地址 0、步长 10，设备仍按协议自动选。

守卫的判定沿用既有的「与打开时快照比对」：一个字没填就关闭不会弹确认，改过才问。
这也是为什么必须先重置再置 `visible`——否则快照本身就是脏的。

### 复测：上一轮记的「操作列被裁」不成立

第十四轮末尾留了一条「1024 触控下报警操作列换行被裁」。这轮在 1024×768 + `hasTouch` 下实测：

| 测量项 | 实测 |
| --- | --- |
| 操作列单元格 | x=793，宽 190，高 **68** |
| 四个动作按钮 | 「确认」「备注」「暂挂」在第一行（y=334），「记录」折到第二行（y=364） |
| 按钮可点高度 | 28px |
| 越界检查 | 无按钮超出单元格右缘或下缘 |

结论：**只是折成 3+1 两行，行高从 59 涨到 68，没有裁切也没有遮挡**。
