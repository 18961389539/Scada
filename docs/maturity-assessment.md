# SCADA 成熟度与功能差距（2026-10-24）

## 评估对象与结论

用户指定的本地 `main` 为 `936d189`。它提供 Modbus TCP 采集、实时监视、基础控制、报警、历史趋势、日/月统计、三种角色和配置库备份，属于初版监控系统，尚未达到可独立承担生产运行的成熟 SCADA 水平。本次未重新构建或运行 `main`，对它的判断来自代码检查。

当前工作位于 `codex/scada-capabilities`。该分支已增加可视化组态、设备对象模板、Modbus RTU、S7、OPC UA 接入、证书与变量浏览导入、采集诊断，以及独立网关采集、补传、远程命令/回执和工程操作，并修复部分控制、报警和令牌校验问题。它处于具备工程化雏形的功能验证阶段；相关功能尚未合并到本地 `main`。完整产品成熟度不能用页面数量或自动测试通过率代替。

## 生产验收优先项

1. **历史数据可靠性。** `HistoryWriterService.FlushAsync` 当前将失败批次放回内存，超过 `ArchiveBatchSize * 10` 会裁掉旧记录；进程崩溃也不能恢复这些待写记录。`RealtimeBus.Subscribe` 的有界通道使用 `DropOldest`，积压过大可丢掉尚未被历史/报警消费的数据。需要持久队列、确认后删除、限额处理、丢数指标和断电/满盘验收。
2. **控制执行闭环。** 当前同一测点的写后回读不能证明电机、阀门等设备已经实际动作。远程命令已增加编号去重、执行授权、未知状态查询和持久回执；本地控制仍需补齐这些状态。设备许可、执行状态和独立反馈仍须建模，并与现场 PLC 约定验收边界。
3. **权限和审计闭环。** 三种全局角色不能表达“只允许操作某车间某设备”。需贯通 HTTP、SignalR、画面动作和后台任务的资源授权，并验证禁用账户或撤销权限后的既有连接处理。
4. **完整恢复。** `MaintenanceService.BackupConfigAsync` 只备份配置 SQLite。历史库、Data Protection 密钥、OPC PKI、运行配置及应用版本需要一同纳入恢复方案，并在隔离环境实际还原；Windows DPAPI 对服务账户及主机的绑定需单独处理。
5. **现场与长稳证据。** 测试点数是规划目标，不是已验证容量。需记录设备数、点数、变化率、轮询周期、客户端数、CPU/内存/磁盘、采集延迟和数据完整率，覆盖断网、重启、慢数据库、满盘及证书到期等场景。

功能推进顺序见 `product-roadmap.md`。当前第 3 项仍缺网关管理界面、完整安装运行及现场验收，第 4～11 项保持待实施状态；生产验收须同时覆盖以上可靠性与权限问题。

当前工作分支的标准 .NET 218 项测试、前后端及模拟器/网关构建和 31 项接口/浏览器场景已验证，详见 `remote-gateway.md`。覆盖既有模块、独立网关采集与补传、中心到实际 TCP 驱动的远程控制及不重发、实际网关的工程操作，以及中心持久设备离线报警、确认、恢复和配置性关闭。网关管理界面、完整安装运行和现场验收仍未完成，不能计为已完成远程网关。真实设备、长稳、规模、SCM 安装及灾难恢复验收仍待完成；未复现的队列恢复检查超时及一次断网恢复进程异常退出分别记在网关验证记录中，根因尚未确定。原有 7 条传递依赖兼容性警告仍在。

- [冗余机制](https://www.docs.inductiveautomation.com/docs/8.3/platform/ignition-redundancy) 包含主备角色、配置同步及故障切换，可作为第 11 项验收参照。
