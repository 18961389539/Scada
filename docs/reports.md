# 报表中心（模板、归档、定时投递）

原有 `/api/reports`（即席日/月聚合）与 `/api/reports/export` 保留，前端菜单改名“即席报表”。新增“报表中心”用于模板化、可归档、可追溯的班报/日报/月报。

## 模板

- 周期：班报（`ShiftStarts`，如 `08:00,20:00`，夜班跨零点）、日报、月报。周期边界按 `Scada:ShiftTimeZone` 计算（与计算任务一致）。班报/日报按小时出行，月报按日出行，末行为“合计/汇总”。
- 列类型：
  | 类型 | 含义 | 汇总行 |
  |---|---|---|
  | TagAvg / TagMax / TagMin | 小时聚合的均值/最大/最小 | 按整周期重算 |
  | TagDiff | 表底/计数器增量：边界值取边界前 1 小时内最后一个好样本（没有则取边界后 1 小时内第一个），区间内逐点累加，读数回落视为表底复位（复位后从 0 起算） | 整周期重算（与逐行之和一致，不会因复位出现负值） |
  | TagSum | 原始好样本的梯形时间加权积分（值 × 小时）× 系数，如功率 kW → kWh 填 1；相邻样本间隔超过 1 小时不桥接，行边界线性插值截断 | 各行求和 |
  | CalcSnapshot | 计算任务周期快照中指定输出（如运行小时任务的 `periodHours`、`periodStarts` 作为运行/停机统计） | 求和 |
  | AlarmCount | 区间内开始的报警数（可设最低级别），仅统计模板区域内测点 | 求和 |
  | Formula | 表达式引用前面的列 `$key`（复用计算测点表达式引擎，无 IO） | 用汇总值重算 |
  | AlarmKpi | 报警 KPI（`output` 为指标键，如 `annunciated`、`peak10Min`、`floodPercent`、`avgAckSec`），模板区域内统计，口径同报警分析（见 `alarm-analytics.md`） | 整期重算 |
- 校验：键唯一且合法、公式只能引用前面的列、测点/计算任务必须存在、班次格式、邮件通道必须为 Email 类型。

## 权限与审计

- 模板列表：区域 View；新建/修改/删除/手动生成：区域 Configure（修改时原区域与新区域都需要）；列引用的测点须可 View，计算任务所在区域须可 View。越权写入记“拒绝”审计。
- 模板写操作记差分审计（`TargetType=ReportTemplate`），乐观版本 `revision` 冲突返回 409。
- 归档列表/详情/下载：报表所在区域 View；无权时 404（不暴露存在性）。
- 每次生成写一条操作日志（`TargetType=ReportRun`）。

## 归档、不可修改与版本

- 生成时把数据快照（`DataJson`）、模板快照（`TemplateJson`、模板版本）存库，并渲染 `.xlsx`（工作表保护）与 `.pdf`，写入 `Scada:ReportsRoot`（默认 `data/reports/{模板}/`）。文件以 `CreateNew` 创建并设只读属性，记录 SHA256。
- 同一模板同一周期再次生成产生新版本（v1、v2…），旧版本保留；唯一索引 (模板, 周期, 版本) 防并发重号（冲突自动重试）。
- 接口没有修改/删除报表的路由（PUT/DELETE 返回 405）；删除模板不删除已生成报表。
- 下载与邮件附件都先校验 SHA256 与数字签名，不一致（被篡改或丢失）下载返回 409 并记失败审计，邮件直接最终失败。归档签名、验证接口与审核/批准电子签名见 `report-signing.md`。

## 定时生成与邮件

- `ReportScheduler` 启动 15 秒后及之后每 60 秒检查启用定时的模板：周期结束且已过 `ScheduleDelayMin`（后端与界面默认都是 10 分钟，等待补传数据）后生成一次。
- 停机回补：每个模板检查最近 `Scada:ReportBackfillMaxPeriods`（默认 3，含最近一个）个已结束周期，从旧到新补齐缺失的定时版本（较早的标 `trigger=backfill`，最近一个标 `schedule`）；结束时刻早于“开启定时”时刻（`ScheduleSinceTs`）的周期不回补，避免刚开启定时就批量生成历史。超过 N 的更早周期需手动生成。
- 界面“生成上一周期”需二次确认（提示会追加新版本且不可删除）。
- 配置了邮件通道和收件人时，生成后写入通知发件箱（`DedupKey=report:{runId}:{channelId}`），复用重试/退避/租约/重启续发/保留清理；附件为归档文件。最终失败出现在通知页“投递失败”并可知悉。

## 归档保留

- `Scada:ReportArchiveRetentionDays` 默认 0（永久保留）。设为正数后，定时任务删除生成时间早于保留期的归档文件（每轮最多 500 份），`ReportRun` 记录、数据快照和哈希保留并标记 `PurgedTs`；下载返回 410，界面显示“文件已按保留期删除”。
- 每批删除写一条系统审计（`报表归档保留期清理`，详情列出报表编号、周期、版本与哈希）。

## 累计列的选择：时间加权积分

原实现“Σ 小时均值 × 1 小时”在采样不均匀（死区归档、变化上送）时偏向密集段，缺数据小时也会被当作 0 或整小时，误差不可控。改为基于原始好样本的梯形积分，并且不桥接超过 1 小时的空档：这与计算任务能耗积分的语义一致，可以单测，结果与采样密度无关。代价是需要读取整期原始数据（月报数据量大时较慢）；要求计量级精度时仍建议用计算任务快照列。

## PDF 库选择

选用 **SkiaSharp**（MIT；底层 Skia 为 BSD-3-Clause）的 PDF 后端：
- 许可宽松，可闭源商用，无收入门槛或传染性条款；
- 自带完整字体栈，能直接使用 TTC/CFF 中文字体（Noto CJK、微软雅黑等），PDF 内嵌子集字体；
- 跨平台原生包（Windows 自带，Linux 用 `SkiaSharp.NativeAssets.Linux`）。

未选：QuestPDF（社区许可对营收超过门槛的企业收费）、iText 7（AGPL）、PDFsharp/MigraDoc（MIT，但对 CFF/TTC 中文字体支持有限）。字体查找顺序：`Scada:ReportFontPath` → Windows 雅黑/黑体/宋体 → Noto CJK/文泉驿 → 系统按“中”字匹配。服务器无中文字体时 PDF 中文会缺字，需配置 `ReportFontPath`。

## 已知限制

- 均值/最大/最小仍来自历史小时聚合（样本均值，非时间加权）。
- 累计与差值读取整期原始数据，长周期、多列时性能未实测。
- 不支持自定义行（按设备分行）、图表、跨区域模板、报表审批/签名流程。
- 回补上限之外的更早周期需手动生成。
