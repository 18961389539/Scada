# 报表签名与电子签名审批

## 归档签名
- 每份报表生成时，对 `.xlsx` 与 `.pdf` 分别做 PKCS#7/CMS **分离签名**（SHA-256，RSA，含签名时间属性，内嵌签名证书），签名（Base64 DER）、签名证书指纹/主题、签名时间与文件、哈希在同一事务写入 `ReportRun`，之后不修改。
- 证书：`Scada:ReportSigningCertPath`（PFX，口令 `Scada:ReportSigningCertPassword`）。未配置时使用数据目录 `keys/report-signing.pfx`，不存在则自动生成自签名证书（RSA-3072，10 年，文件权限 600，启动日志告警）。**显式配置的证书不存在时签名失败**，不会悄悄换成自签名证书。
- `Scada:ReportSigningEnabled`（默认 true）为 false 时只做 SHA256。
- 签名失败（证书不可用等）**不阻止归档**：报表照常生成，记录 `SignatureError`，生成审计结果写“成功，但签名失败：…”，界面显示“未签名”。
- `keys/` 已在备份范围内；主备部署须同步该目录（或配置同一 PFX），否则备机接管后签名证书不同（旧报表仍可验证，界面标注“非当前证书”）。

## 验证
- 下载：先校验 SHA256，再校验签名（内容摘要、签名、签名证书指纹与记录一致）。任一失败返回 409 并记失败审计（“数字签名无效”可识别同时篡改文件和数据库哈希的情况）。邮件附件走同一校验。未签名的旧报表照常下载，响应头 `X-Report-Signature: unsigned`；已签名为 `valid`。
- `GET /api/report-runs/{id}/verify`：两个文件的存在/哈希/签名结论、证书信息（自签名/链是否受信任/是否当前证书）、电子签名记录逐条验证结果与审批状态，`ok` 为总结论。
- `GET /api/report-runs/{id}/signature?format=pdf|xlsx`：下载 `.p7s`，可离线验证：
  `openssl cms -verify -binary -inform DER -in 报表.pdf.p7s -content 报表.pdf -noverify -out /dev/null`
  （自签名证书用 `-noverify` 跳过链校验；配置 CA 证书时改用 `-CAfile`。）
- `POST /api/report-runs/{id}/verify-file`（请求体为文件原始字节，≤64 MB）：核对外发副本是否与归档一致且签名有效。
- 报表中心“验证 / 签署”对话框提供以上全部操作。

## 电子签名审批（可选）
- 流程：审核（review）→ 批准（approve）。每步结论为通过或驳回；**任一步驳回即终结**，需更正时重新生成新版本。已批准后不再接受签名。审批是可选的：未审批的报表照常可下载、可邮件投递。
- 权限：审核需报表所在区域 View；批准需区域 Configure，且**批准人不能与审核人相同**。
- 每次签署必须填写理由（≤500 字）并重新输入本人密码；密码错误计入与登录相同的限流（5 次/5 分钟锁定，键为 `esign:` 前缀），每次失败写“拒绝”审计。
- 只能对完好的归档签署：文件存在、哈希一致、归档签名有效，否则 409。
- 每条签名记录（`ReportApprovals`，只追加）保存签名清单 JSON（报表编号、模板、周期、版本、两个文件的 SHA256、步骤、结论、用户、理由、时间），并由服务器证书签名。验证时既验签，也按记录重建清单比对，记录被改动（如改理由）即判无效。成功签署写审计，详情含理由与哈希。

## 局限
- 签名者是**服务器证书**，签名人身份由“登录 + 密码复核 + 审计 + 服务器签名的清单”证明，不是个人证书/UKey 签名；需要个人数字证书或第三方可信时间戳（RFC 3161）时需再扩展。
- 自签名证书只能证明“由本系统生成且未被修改”，对外具法律效力需配置 CA 颁发的证书。
- PDF 内未嵌入可视签章（签名为外置 `.p7s`）。
- 证书过期只告警，不阻止签名；证书轮换后旧报表仍以内嵌证书验证。
