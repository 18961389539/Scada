## 已实现的持久队列

`Scada.Gateway` 当前是库项目。`GatewayAgentStore` 为网关安装生成并持久保存 `StreamId` 和全局递增序号，使用独立 SQLite 文件，不复用中心配置数据库。

- 采集批次包含设备 ID、配置版本摘要、工程量、质量、采集时间及可选源时间。单批最多 5000 点，拒绝重复测点 ID、非法质量、非有限数值等无效内容。错误文本截断为最多 1000 字符，不因诊断文本过长而丢弃测量。
- 采用 WAL、每连接 `synchronous=FULL` 及显式写事务，包内容、序号和积压计数一起提交。每次访问独立打开连接，多个设备并发写入仍按事务分配连续序号。
- 队列同时保存精确 JSON 和 SHA-256；重试发送同一份内容。读取发现校验不符时停止发送，不自行删除或重建队列。
- 只有数据流和队首序号均匹配的确认才删除该包；重复确认幂等，越过队首或错误数据流的确认被拒绝。确认后重新打开存储，序号继续递增。
- 待发送 JSON 默认限额 256 MiB，满时拒绝追加，不裁掉旧数据。该限额是待发送包的 UTF-8 字节数，不是 SQLite 数据库、空闲页、WAL、命令日志及配置的总磁盘限额。具体离线容量仍需按点数、周期和变化量测算。
- 使用数据库应用标识及版本检查，拒绝误指向已有其他数据库或不受支持的版本，不自动覆盖旧文件。错误或损坏的数据不会通过自动清空来“恢复”。

`GatewayTelemetryUploader` 每次尝试只发送队首包，在得到匹配确认前保留本地记录。它使用正常的系统 HTTPS 证书验证，不自动跟随重定向；只有明确启用测试选项时才允许回环 HTTP。身份、会话及包摘要放在请求头，地址不允许携带用户名、密码、查询参数或片段。响应读取也受超时和 4 KiB 确认大小限制。

上送组件的丢确认与超时测试使用测试服务器；中心已注册实际 `/api/gateway-agent/telemetry` 接口，另有接口场景验证中心认证、会话、接收及归档。独立网关运行进程仍待接入，尚未完成完整进程的网络故障演练。

## 中心认证、配置与接收

网关使用独立 `Gateway` HTTP 身份，不使用普通用户 JWT。管理员创建或轮换时得到一次随机密钥，中心只保存其 SHA-256；列举、详情和操作日志不返回密钥或摘要。普通用户 JWT 不能调用网关进程接口，网关密钥也不能访问普通用户或管理接口。

中心默认要求实际 HTTPS 请求。`Gateway:AllowLoopbackHttp` 默认关闭，只在显式开启且对端 IP 为回环地址时接受 HTTP；测试启动器明确开启此选项。中心不依据任意客户端提交的转发头认定请求为 HTTPS。生产部署须配置正确的 TLS 接入。

握手带协议版本、安装数据流和本次进程 ID。活动租约默认 30 秒，同进程握手重试返回原会话，其他进程在租约有效时被拒绝。续约、取配置和上送都再次检查当前密钥、启用状态、会话及期限；释放会话、停用或轮换密钥使原会话失效。租约到期后重新握手会获得新会话。

设备增加可空 `GatewayId`，迁移后原设备保持本地采集。中心不为远程设备创建驱动；驱动工厂也拒绝误用。切换采集位置要求设备停用、原本地任务实际退出；未响应取消的旧任务仍保留引用，在实际完成前不能视为已停止或启动替代任务。由一个网关迁出时，还要求它已确认该设备的停用配置。

配置按设备、测点和凭据生成版本摘要并保存不含明文密码的归档元数据。仅经过认证的当前网关会话可取得自己分配的设备、测点和所需 OPC 密码，响应禁止缓存；密码仍由中心 Data Protection 解密，运行进程的本地保护及应用流程尚待完成。确认未下发的版本或提交其他网关的设备/测点会被拒绝。

数据包通过版本、摘要、数量、类型、归属、时间及顺序检查后，在 `synchronous=FULL` 事务中写入中心收件箱并推进接收进度，提交后才回复确认。默认全局待处理 JSON 限额为 512 MiB，单包上限 16 MiB；满时返回 429，不确认新包。重复接收不再入队，最新重复序号内容变化、乱序和错误数据流会被拒绝。

消费者按每个数据流的序号处理，使用当时配置的归档策略与持久游标写历史。历史按测点/时间幂等插入，完成后才提交处理进度并删除收件箱内容；历史已提交但处理进度失败时重试不会重复插入。失败包保留错误及重试时间，不阻止其他流处理。

只有当前会话、当前已确认配置、新鲜采样时间且晚于现有实时值的数据才更新实时缓存并进入报警输入。旧配置和迟到批次可补历史，不能覆盖当前值。失联时网关连接状态会离线，测点沿用龄期/过期显示；中心推断离线质量区间的持久归档仍需随历史可靠性完善。中心本地历史通道排除远程测点，避免与网关归档重复写入。

当前远程控制、测试读取、详细诊断和 OPC 工程操作返回明确的“尚未贯通/未下发”，不转而连接中心主机的端口或证书。它们仍属于必须完成的交付范围。

### 当前接口

| 范围 | 接口 |
|---|---|
| 管理员 | `GET/POST /api/gateways`、`GET/PUT /api/gateways/{id}` |
| 密钥/会话 | `POST /api/gateways/{id}/rotate-key`、`POST /api/gateways/{id}/release-session` |
| 采集位置 | `POST /api/gateways/assignments/{deviceId}`，正文为可空 `gatewayId` |
| 网关进程 | `POST /api/gateway-agent/hello`、`GET /api/gateway-agent/configuration`、`POST /api/gateway-agent/heartbeat`、`POST /api/gateway-agent/telemetry` |

进程请求使用 `Authorization: Gateway <编号>:<密钥>`；握手以外同时提供 `X-Scada-Session`，遥测还提供 `X-Scada-Payload-Sha256`。只有显式匹配确认才能删除本地队首包。中心网关管理界面和运行进程安装说明尚待实现，不应手工把密钥放进 URL。

SQLite 提交设置依据官方 [WAL 说明](https://www.sqlite.org/wal.html)及 [synchronous 说明](https://www2.sqlite.org/pragma.html)。这些设置加强提交持久性；实际存储设备、操作系统和掉电行为仍需验收，不能据此宣称绝对不丢数据。

## 与采集循环的连接

`ICollectorJournal` 是可选的批次持久记录接口，`GatewayCollectorJournal` 将配置版本固定到当前采集运行实例。

- 正常读取先计算完整工程量批次，等待持久提交，再更新实时缓存并发布。持久记录尚未完成时不提前发布正常样本。
- 通信故障也形成带原因的质量批次，便于之后补传。持久队列满或持续无法写入时，诊断明确显示任务异常暂停；缓存标记通信故障，已保存队列保留。网关监督进程的自动恢复仍待接入。
- 控制写入及回读后也尝试持久记录；记录失败返回“写入已发送、持久记录失败”，不重复下发物理写入。它不能将本来已发出的命令描述为从未执行。

现有中心采集进程没有注册该接口，保持原来的历史流程；这次改动**没有完成第 6 项的中心历史持久缓冲**。

## 本地命令日志

命令以不可变 ID、设备/测点、工程值、配置版本及截止时间保存。重复 ID 内容变化被拒绝，同一命令只能从 Reserved 成功进入 Started 一次，终态结果不能被重复请求覆盖。

执行授权令牌和离线配置的存储接口接收调用方已经保护的内容，生产调用方仍须接入持久密钥及 Data Protection；网关配置传输模型中的 OPC 密码只能在受认证 HTTPS 通道中使用，不可写入普通日志。

恢复必须持有当前安装目录的独占文件租约，不能只凭 PID、锁文件内容或历史状态判断旧进程已经停止。恢复将 Reserved 归类为未下发，将 Started 归类为结果未知；二者都不重新开始执行。结果保留到中心确认，已确认且已过期至少 7 天的记录才可清理。命令日志默认上限 100000 条，满时拒绝新命令，不覆盖旧记录。

本地状态机解决的是进程内/本地重开恢复约束。中心命令领取、授权响应丢失、旧会话隔离、实际执行与回执对账仍必须按上表完成后才能交付远程控制。
