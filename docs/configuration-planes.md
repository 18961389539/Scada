# 配置平面

本系统的配置分成三层。分层的目的是：备份还原、主备复制和页面改动能各自只碰到该碰的东西。

## 1. 部署平面

存放位置：站点配置文件（由 `StartupPaths.ResolveSiteSettings` 定位，通常是 `data/appsettings.Site.json`）、环境变量和命令行。

属于这一层的有：数据目录与库路径、JWT 密钥、监听地址、反向代理、`Ha:NodeId` / `Ha:PeerUrl` / `Ha:SharedKey`、备份口令等**本机部署项**。

- 完整备份**不打包**站点文件；离线还原到另一台机器时应保留目标机的站点文件。
- 配置快照、工程包和主备配置复制都不包含这一层。
- 不要把 JWT 或 `Ha:SharedKey` 写入配置库。

## 2. 厂级运营组态

存放位置：配置库（`config.db` / `scada.db`）。

属于这一层的有：测点与设备、报警规则、画面、计算任务、权限，以及**工厂日历（班次时区）**。页面可改、且会影响按日切分或历史分桶的设置，只能放在这一层。

- 进入完整备份的 `config.db`。
- 随主备配置复制到达备机。
- 写入工厂日历后，历史工厂会按既有整点/半点时区规则重跑 `AggregationOffset` 对齐，报表、OEE、计算任务和通知会重读时区。整点时差（含 UTC+8）与 UTC 整点重合，已有小时行不必迁移；半点时区则在回补窗口内按本地整点重写。

`Scada:ShiftTimeZone` 仍可作为启动回退和首次种子来源。升级后若配置库尚无厂级日历行，会把站点文件或进程配置里的值写入配置库一次。之后以配置库为准，页面不再回写站点文件。

## 3. 运行时

存放位置：运行库和历史库。

属于这一层的有：报警事件、命令回执、OEE 样本、配方下发记录、操作审计，以及按测点编号分文件存储的历史。删除组态时不对历史做在线大清理。配置实体删除时必须清理的运行表见 `RuntimeCleanupCatalog`。

## 备份清单（完整备份包含什么）

完整备份打包：配置库、运行库、历史库、历史暂存、历史缺口日志、报表归档、Data Protection 密钥、OPC PKI 与清单。不包含站点配置文件、JWT 或仅属于本机的部署项。不提供在线一键恢复接口，也不在网页里录入备份口令。
