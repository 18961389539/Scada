# 计算任务：累计器、运行小时、能耗积分与受限脚本

路线图第 4 项的扩展部分。表达式计算测点见 `calculated-tags.md`。

## 选型：先评估现有表达式引擎

现有 `TagExpression` 是自研的数值表达式解释器。特点如下：

- 编译成 AST 再解释执行；只有数值、`#编号` 测点引用、算术/比较/逻辑运算和白名单函数（if/min/max/abs/sqrt/pow/clamp/round/三角/对数）。
- 没有循环、字符串、对象、反射、用户函数，也没有 IO 入口。
- 编译时有上限：最多 512 个节点、64 层嵌套、64 个引用。执行时间与 AST 大小成正比。
- 已与质量传播、定义版本、依赖图、区域授权和审计集成，并有大量测试。

候选方案对比：

| 方案 | 隔离 | 时间/内存限制 | 依赖与维护 | 结论 |
|---|---|---|---|---|
| Roslyn C# 脚本 | 进程内运行完整 .NET。.NET Core 没有 CAS/AppDomain 沙箱，只能靠 API 黑名单，易被绕过 | 无法可靠限制单个脚本的内存；超时只能协作式取消 | 编译器体积大，冷启动慢 | 否：做不到“无 IO/网络” |
| Jint（JS）/ MoonSharp（Lua） | 解释器沙箱较好，有步数/内存/递归上限 | 有 | 新增第三方依赖，另需桥接质量、白名单和审计；语法与计算测点不一致 | 可行，但对当前需求偏重 |
| NCalc 等表达式库 | 与现有引擎能力相当 | 无步数限制 | 新增依赖，没有收益 | 否 |
| **在现有引擎上扩展“赋值语句序列”** | 沿用现有的无 IO 构造，读写入口只有引擎提供的回调 | 加入步数计数和墙钟截止；内存由结构上限约束 | 零新依赖；语法与计算测点一致，复用全部校验与测试 | **采用** |

结论：需求是“数值计算 + 定时 + 读写指定测点”，不需要循环或通用编程，扩展现有引擎的风险和代价最小。累计、运行小时、积分这类有状态的计算不放进脚本，改由内置任务类型实现。这样断电续算、回绕处理和坏质量策略可以在代码中统一实现并测试，不依赖用户在脚本里写对。

引擎为脚本做了以下改动：

- 增加 `$变量`。只有脚本可用，普通计算测点仍不允许。
- 增加 `ExpressionContext`。测点读取和变量都经它访问；每个节点计一步，超过步数上限或墙钟截止即抛错。

## 任务类型

输出写入自动生成的**派生测点**（`TagKind.Derived`，名为“任务名.输出名”，区域与任务一致，只读）。派生测点与普通测点一样参与实时、趋势、报警、报表、画面，也可以作为计算测点的输入。测点配置页不能直接修改或删除派生测点，控制接口也拒绝写入。

### 累计器（Accumulator）

- **脉冲计数**：按计数差累计，乘以脉冲当量。
  - 回绕：设置了满量程，且读数从上半区跳到下半区时，按回绕补齐（`max - last + raw + 1`）。
  - 复位：其他回落视为设备计数器复位，从 0 开始计。
  - 跳变：可设单次增量上限，超过的增量丢弃并记录事件。
  - 坏质量期间不更新基准，恢复后的差值会补上这段时间。重启后同理：设备计数器在停机期间仍在累加，基准已持久化，所以这部分会计入。
- **瞬时流量积分**：梯形积分，换算系数把流量单位转换到“每秒”。相邻两次有效采样的间隔不超过“最大间隔”才计入；负值按 0 处理。
- 输出：`total`（总累计）、`period`（本周期）。

### 设备运行小时（RunHours）

- 输入值大于运行阈值视为运行。按上一次的运行状态累计区间时长，停→运记一次启动。
- 输出：`hours`、`periodHours`、`starts`、`periodStarts`、`sinceMaintenance`、`maintenanceDue`（1/0）。
- 维护提醒：自上次维护起的运行小时达到阈值后，`maintenanceDue` 置 1，页面显示“到期需维护”。对该派生测点配置报警规则，即可走完整的报警、通知和升级流程。“维护完成”需要 Control 权限，会把维护基准移到当前累计值，并留快照、记审计。

### 能耗积分（Energy）

- 对功率做梯形积分得到电量（kW 配合系数 1/3600 得到 kWh）。
- 分时时段（尖/峰/平/谷）：按积分区间中点的本地时间归段，支持跨零点，未覆盖的时段计入“平”。
- 输出：`total`、`period`、`period_sharp/peak/flat/valley`。

### 坏质量策略（流量、能耗、运行小时）

坏质量包括：缺失、非 Good、非有限值，或者采样时间早于“最大间隔”。

| 策略 | 行为 |
|---|---|
| Hold（默认） | 沿用最后一个好值，最长不超过“最大间隔”，超出后视为未知 |
| Skip | 该区间不积分。运行小时在状态未知时既不累计时长，也不计启停 |
| Zero | 按 0 计（流量、功率为 0；运行小时为停机） |

值未知时，输出质量标为 Uncertain，但累计值保留。

### 周期复位与快照

- 复位周期可选不复位、按班、按日、按月。
- 班次起点使用 `HH:mm` 列表，如 `08:00,20:00`；零点到第一个班次起点之间的时段归入前一天的最后一个班次。
- 时区使用 `Scada:ShiftTimeZone`。
- 进入新周期时，先把复位前的全部数值写入 `CalcJobSnapshots`，再清零 `period*`。
- 手动复位需要 Control 权限，同样留快照并记审计。

### 断电续算

- 运行状态（累计值、计数基准、周期、维护基准、脚本上次写值）每 `Scada:CalcStatePersistSec` 秒（默认 10 秒）写入 `CalcJobStates`。周期复位时和进程正常停止时也会立即落盘。
- 重启后从落盘值继续。停机期间不做积分，也不计运行时长：重启后清掉上次采样时刻，从第一次新采样重新开始计算。
- 异常断电最多丢失一个落盘周期的增量。脉冲计数例外：设备计数器仍在累加，这部分会补回。

## 受限脚本（Script）

```
// 每行一条，或用分号分隔
$avg = (#1 + #2) / 2
@avg = $avg                       // 输出 → 派生测点 “任务名.avg”
@night = if($hour >= 22 || $hour < 6, 1, 0)
#9 = clamp($avg, 0, 100)          // 写现场测点
```

- 赋值目标只有三种：`$变量`（先赋值后使用）、`@输出`、`#测点`。右侧使用与计算测点相同的表达式语法。
- 内置变量：`$dt`（距上次执行的秒数）、`$hour`、`$minute`、`$weekday`、`$day`、`$month`。
- **白名单**：读取的测点必须在“可读测点”中。写入目标必须在“可写测点”中，且必须是可写的现场测点。派生结果只能用 `@输出`。
- **沙箱与上限**：
  - 编译期：脚本最长 16 KB、最多 200 条语句，单个表达式最多 512 个节点；可写测点最多 16 个，可读测点最多 64 个，输出最多 32 个。
  - 执行期：每次执行最多 `Scada:CalcScriptMaxSteps` 步（默认 10 万），墙钟上限 `Scada:CalcScriptTimeoutMs`（默认 50 ms）。
  - 内存：语言里没有任何能分配数组或字符串的构造，内存只与语句数成正比，由上述编译期上限约束。.NET 进程内无法为单个脚本单独设硬性内存上限，这一点如实说明。
  - 执行周期不少于 1 秒。
  - 没有循环、字符串、函数定义、文件、网络或反射入口。
- **读取**：任一输入缺失、非 Good，或者早于“输入有效期”，整次执行失败：输出变为 Bad 并显示原因，不进行任何写入。
- **写测点**：
  - 只在目标值变化时下发，避免周期性刷写现场。
  - 以**保存脚本的用户**为执行身份。保存时，该用户须对每个可写测点有 Control 权限；运行时每次写入都会重新检查该身份的 Control 权限，权限收回后写入被拒，并记“拒绝”审计。
  - 写入经 `ControlCommandService` 下发，与人工控制一样做值范围校验、写入操作日志（操作者显示为“用户（计算任务 名称）”），并且只发往启用的设备。
  - 写入失败或被拒时，不记为“已写”，下次执行会再试，事件显示在列表中。
  - **执行身份失效告警**：有可写测点的脚本每分钟（失效期间每次）核对执行身份——用户被删除、停用或对任一可写测点失去 Control 时，整次不执行、输出 Bad，并在 `/health` 产生 `calc_job_identity` 告警（状态 degraded），诊断包 `notifications.json` 的 `calcJobErrors` 也会列出；由有权限的人员重新保存任务（执行身份随之更换）或恢复权限后告警自动消失。

## 权限与审计

| 操作 | 要求 |
|---|---|
| 查看列表/快照 | 任务所在区域的 View |
| 新建/修改/删除 | 任务区域的 Configure；修改时新旧区域都需要；还须能查看所有输入/可读测点 |
| 脚本可写测点 | 保存人对每个可写测点有 Control |
| 手动复位、维护完成 | 任务区域的 Control |

- 所有写操作都记 `OperationLog`，TargetType 为 `CalcJob`，内容是前后差分；被拒绝的操作也记审计。
- 版本号用于并发控制，不一致时返回 409。任务类型创建后不能修改。
- 派生测点仍被计算测点或其他任务引用时，不能删除对应的任务或输出（409）。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/calc-jobs` | 任务、输出测点、运行状态（当前值、周期、最近错误/事件、脚本步数与耗时） |
| POST / PUT / DELETE | `/api/calc-jobs[/{id}]` | 新建 / 修改（带 revision）/ 删除（`?revision=`） |
| POST | `/api/calc-jobs/{id}/reset` | 手动复位 |
| POST | `/api/calc-jobs/{id}/maintenance-done` | 维护完成 |
| GET | `/api/calc-jobs/{id}/snapshots` | 复位快照 |

前端：菜单“计算任务”（`/calc-jobs`）。表单按任务类型显示对应字段，包括分时时段编辑和快照查看。

## 已知限制

- 输入按任务周期从实时缓存采样，不是逐个事件积分。周期内的快速脉动按采样点近似；需要更高精度时，可缩短周期，或使用脉冲计数。
- 只做中心侧计算，不下沉到网关；网关断线期间的数据靠补传进入历史，不会回溯积分。
- 分时时段按积分区间中点归段，区间跨越时段边界时不拆分。周期较短时误差可以忽略。
- 脚本是周期任务，暂不支持按事件触发（如“某测点变化时执行”）。
