# 带分支的顺控

顺控（`ControlSequence`）的步骤从线性列表扩展为步骤图。执行、权限、确认、双人复核和审计规则不变，见 `field-control.md`。其中，写测点步骤仍然经过控制闭环的全部检查与回读。

## 步骤类型

每个步骤都有编号 `id`（1～40 个字母、数字、`_` 或 `-`）和类型 `type`。执行从**第一步**开始。“下一步” `next` 为空时，顺延到列表中的下一步；最后一步之后运行结束。

| 类型 | 字段 | 说明 |
|---|---|---|
| `write` 写测点（默认） | `tagId` `value` `confirmExpression` `timeoutMs` `delayMs` `next` | 下发并回读，写后延时，再在超时内等待完成条件成立 |
| `wait` 等待 | `expression` `timeoutMs` `next` | 在超时内等待条件成立，超时判失败 |
| `condition` 条件分支 | `expression` `then` `else` | 条件成立转 `then`，否则转 `else`（为空则顺延）。**引用测点无有效值或表达式无效时判失败**，不猜测走哪个分支 |
| `parallel` 并行 | `branches`（2～8 个分支首步） `join` | 各分支同时执行，必须汇合到 `join` |
| `join` 汇合 | `joinMode`：`all` / `any` `next` | `all`：全部分支成功才继续，任一分支失败则其余分支停止，整体失败。`any`：任一分支成功即继续，其余分支停止；全部失败才判失败 |
| `jump` 跳转/循环 | `target` `maxIterations`（1～1000） | 每次执行都计数，超过上限判失败（“循环超过上限 N 次”） |
| `end` 结束 | — | 结束本次运行 |

分支停止的方式：正在进行的写入不会被打断，写入完成后才停止；正在等待的条件（完成条件、等待步骤、写后延时）会立即结束。

## 超时与失败处理

- 每个写步骤和等待步骤都有自己的超时（100～600000 毫秒）。
- 失败处理 `onFailure`（并行步骤的失败处理在汇合失败时生效）：
  - `stop`（默认）：停止整个运行（在并行分支内则停止该分支），状态为失败，其余未执行的步骤记为“跳过”。
  - `continue`：本步记为失败后顺延。运行最终记为“完成”，消息中列出按配置继续的失败步骤。
  - `goto`：转到 `onFailureGoto`，例如安全停机或回退步骤。失败处理路径执行完后，运行**仍记为失败**，消息中注明“已转入失败处理步骤”，提醒人工核对。
- 中止和服务停止不会触发失败处理，以免因此转入其他步骤继续下发。
- 运行总执行步数上限为 10000，作为额外保护。

## 静态校验（保存与工程导入时）

保存或导入时逐项检查，任一项不满足都会被拒绝：

- 编号唯一，引用的步骤必须存在，类型必需的字段齐全，条件和完成条件表达式有效，写入测点存在且可写；
- **不可达步骤**：所有步骤都必须能从第一步到达（失败转向也计入）；
- **汇合**：并行步骤必须有汇合，且汇合必须是 `join` 类型；每个汇合只能属于一个并行步骤；汇合只能经由并行到达；
- **分支路径**：并行分支的每条路径都必须到达自己的汇合，不能中途结束运行，也不能走到其他汇合（嵌套并行可以）；
- **无上限循环**：去掉跳转步骤的边之后，图必须无环。也就是说，循环只能通过设置了上限的跳转来实现（`next` 指回前面的步骤、失败转向自身等都会被拒绝）。

## 运行记录

- `ControlSequenceRun.steps` 中每个步骤一条记录，包含 `stepId`、类型、状态、最后一次的消息和起止时间，以及执行次数 `executions`（循环中同一步骤可能执行多次）。
- 没有执行到的步骤记为“跳过”。

## 重启与兼容

- 服务重启时，运行中的顺控仍然只标记为“中断”，**从不自动续跑**，与原规则相同。
- **旧顺控兼容（迁移）**：升级前保存的线性步骤没有 `id` 和 `type`，读取时自动规范化为 `write` 类型，编号依次为 `s1`、`s2`……，按原顺序执行，行为不变；数据库不需要改写。
- **工程包**：纯线性的写步骤顺控按旧格式导出，与旧工程包和旧快照逐字一致，比较时不会产生无意义的差异。含分支的顺控导出完整步骤图，带 `id`，表达式中的测点写为 `#{测点键}`。旧工程包导入时同样会被规范化。

## 已知限制

- 还没有图形化的流程图编辑器，界面以表格方式编辑步骤图；保存时由服务端做完整校验。
- 并行分支写入同一设备时，由采集层按设备串行下发，实际上并不同时。
- “任一”汇合停止其余分支时，正在进行的写入会执行完毕。如果这类写入在工艺上不可接受，应改为在分支内用条件步骤判断。
- 分支与循环只在中心侧编排，不能替代 PLC 内的顺序控制与安全联锁。
