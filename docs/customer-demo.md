# 客户演示数据

## 一键启动

在仓库根目录的 PowerShell 中执行：

```powershell
.\tools\DemoSetup\Start-Demo.ps1
```

脚本构建后端与 Modbus 模拟器；缺少前端产物时会安装依赖并构建前端。
准备好后访问 `http://127.0.0.1:18927`，使用示例管理员 `admin` / `admin123` 登录。
演示仅监听本机地址，使用独立的 `.local/customer-demo` 数据目录，不修改现有项目数据库。
模拟器使用本机 TCP 1502 端口。端口被占用时脚本拒绝启动，不终止其他程序。
按 Ctrl+C 结束演示时，脚本也会关闭由它创建的模拟器。

前提：.NET 10 SDK；首次构建前端时还需要 Node.js 和 npm。支持 Windows PowerShell 5.1。
此入口是开发演示，不是生产服务安装；不要在演示实例中连接真实生产设备。
脚本显式设置 `Scada:DemoMode=true` 和站点名 `SCADA Customer Demo`，登录页及顶栏会显示演示标识。
生产环境默认 `DemoMode=false`，不预填账号、不显示演示密码；灌入示例数据本身不会开启演示登录。

## 数据范围

| 场景 | 内容 | 演示重点 |
| --- | --- | --- |
| 公用工程 | 锅炉、配电总表、螺杆空压机、循环冷却水站 | 温度、压力、流量、累计能耗、设备状态 |
| 智能装配 | A01 电机装配线 | 产量、良品率、节拍、压装压力、锁付扭矩 |
| 质量检测 | EOL 电性能检测台 | 电压、电流、绝缘、绕组电阻、转速、振动、温度、测试时长 |
| 监控画面 | 6 个已发布且可继续编辑的设备总览 | 实时数据绑定、测点量程与单位 |
| 历史趋势 | 最近 7 天，每 5 分钟采样；含 5 分钟和小时聚合 | 多变量趋势、能耗比较、历史报表 |
| 报警 | 14 条规则、70 条历史事件 | 提示/警告/严重等级、已确认与未确认、恢复与处理过程 |
| 生产分析 | 1 条产线、3 个产品、白班/跨午夜夜班、4 类停机原因 | OEE、产量、不良率、计划停机、故障、缺料与原因分析 |
| 生产历史 | 最近 7 天，168 条停机事件与 168 条产量记录 | 按班次/日期分析、停机原因排序 |
| 质量追溯 | 两种 SN 来源、168 条完整检测记录、7 条缺 SN 失败记录 | 精确 SN 查询、检测详情、两种 SN 模式与失败处理 |
| 配方 | 1 个装配模板、3 个产品配方、每个配方 2 个版本 | 标准节拍/锁付扭矩、版本对比、模拟器写入 |
| 报表 | 能源日报、锅炉运行日报、装配线生产日报 | 时段统计、累计量差值、蒸汽量积分与 OEE |

所有数据均为合成示例。名称、记录或操作来源中的 `DEMO` 表示非真实现场数据。
追溯样本包含正常产品、绝缘电阻偏低产品和振动超限产品。
检测不合格也应保存检测结果；采集成功握手仍为 2，不等于产品合格。
新建演示库的检测任务将“检测判定”字段映射为 1 合格、2 不合格；查询页单独显示检测结果和 PLC 应答。
升级已有演示库时，旧记录保持“未判定”，不会根据新规则自动回判。
需要演示新结果快照时，请使用下方的新独立目录启动方式，不要删除或改写旧记录。
缺 SN 的采集失败只记录失败尝试，不伪造产品记录，回复值为 3。

## 推荐演示顺序

1. **设备与测点**：查看三区域、六套设备，以及测点说明、单位、量程、采集地址。
2. **实时监控**：打开锅炉、装配线和检测台画面；模拟值持续变化，不需要真实 PLC。
3. **历史趋势**：选择电压、电流、功率或温度，查询最近一天或最近七天。
   相同单位共用曲线面板，不同单位及未配置单位的测点分开显示，各面板同步缩放与回放。
   布尔测点在 1 小时、6 小时原始数据范围内按 0/1 阶梯展示；较长范围显示聚合样本均值，分数值不表示实际中间状态。
4. **质量追溯**：查询 `DEMO-MTR-00-A001` 查看合格产品；查询 `DEMO-MTR-00-A004` 查看绝缘偏低；查询 `DEMO-MTR-00-A008` 查看振动超限。
5. **PLC SN**：查询数值 SN `2600001`，对比 PLC 来源与网页扫码来源。
6. **生产分析**：选择 A01 产线及最近七天，展示良品、不良品、OEE、班次和停机原因分布。
   日常停机补录、原因归类、确认与产量修正已移至“生产与质量 → 生产事件”，不再混在工程字典配置中。
7. **报警记录**：查看 `[DEMO]` 历史事件、报警等级、发生/恢复时间和确认状态。
   实时与历史记录均先在服务端按状态、等级、关键词及测点筛选，再分页展示全部匹配记录；批量确认只作用于当前页可确认项。
   总览将“活动未确认”和“已恢复待确认”分开统计，点击对应卡片进入相同状态的报警列表。
   “报警泛滥”反映统计窗口内的触发频率，不是当前活动数；总览显示窗口、次数及进入阈值，报警页补充解除阈值、抑制策略和首出记录。
8. **配方**：查看同一产品的两个版本，比较试制与优化后的节拍；只向本机模拟器演示下发。
9. **报表**：在“业务报表 → 模板与生成”选择上述日报模板；生成后自动进入“已生成归档”查看、下载和签核。
   报表会按需生成实际归档文件，不预置虚假下载文件或签名。“测点统计”则用于临时的日/月查询与 Excel 导出。

追溯任务默认禁用，报表模板默认不定时执行，不会自动发起采集或外发通知。
要演示新产品采集，在任务配置中启用网页扫码任务，绑定一个未使用的 SN，
再将检测台的“检测触发”测点写为 1；成功后该地址应变为 2，且能按该 SN 查询记录。
进行下一次采集前先写回 0，再换新 SN、重新写入 1。
PLC SN 演示使用独立的“PLC SN 检测触发”测点，避免两种任务争用握手地址。

## Git 与数据复现

应纳入 Git 的是信号 JSON、检测样本 JSON、初始化源码、启动脚本、测试与本说明。
它们随仓库克隆和 `dotnet publish` 一起生效；两个 JSON 嵌入程序集，不依赖本机私有文件。
不要提交运行生成的数据库、日志、证书私钥、管理员令牌或发布目录。

- `src/Scada.Core/Demo/signals.json`：实时和历史共用的数值、波动周期及累计量变化。
- `src/Scada.Core/Demo/traceability.json`：可直接维护的 SN 样本与九项检测值。
- `src/Scada.Data/DatabaseInitializer.cs`：设备、区域、测点与基础锅炉画面。
- `src/Scada.Data/DatabaseInitializer.Demo.cs`：业务记录、画面、配方、报表及历史生成。
- `tests/Scada.Engine.Tests/DatabaseUpgradeTests.cs`：数据关联、信号覆盖与重复初始化验证。

首次空库启动且 `Scada:SeedDemoData=true` 时才生成示例。重复启动不重复灌入，
已有设备的数据库不会追加或覆盖本示例。时间以首次生成时刻为基准，向前覆盖七天。
要在下次演示时刷新时间范围，指定新的独立目录，不需要删除旧数据：

```powershell
.\tools\DemoSetup\Start-Demo.ps1 -DataPath .local/customer-demo-next -Port 18927
```

统一发布的后端也支持 `--Scada:SeedDemoData=true`，但务必同时指定独立的配置库、
历史、备份、日志和报表目录。完整发布与生产启动要求见 [统一发布说明](publishing.md)。
