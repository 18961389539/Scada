# 主备高可用

两台中心服务器组成一主一备（热备）。主机采集、归档、报警、控制、计算、报表、通知与定时备份；备机只做复制，不采集、不下发控制、不执行任何后台写任务，网关和写请求被拒绝并被告知主机地址。默认不启用（`Ha:Enabled=false`），单机部署行为不变。

## 角色与防双主

- **心跳**：两节点每 `HeartbeatMs`（默认 1 秒）互查 `/api/ha/peer/status`，请求带 `X-Scada-Ha-Key`（`Ha:SharedKey`）。
- **仲裁租约**：`Ha:WitnessPath` 指向第三台机器上的共享目录（SMB/NFS），其中 `lease.json` 记录持有者、任期、到期时间与交接对象。读改写在 `lease.lock` 独占打开期间完成（比较并交换），同一时刻至多一个持有者。仲裁接口 `IHaWitness` 可替换为数据库或 HTTP 仲裁服务。
- **主机**每次心跳续租 `LeaseMs`（默认 6 秒）。续租失败且本地记录的租约期限已到，立即**自我隔离**降为备机——即使它与备机之间网络仍通。
- **备机**仅当租约过期再加 `ClockSkewMs`（默认 1 秒）、且对端不再自称主机时才接管，任期加一。两节点必须 NTP 对时，偏差应远小于 `ClockSkewMs`。
- **无仲裁**：只按 `PreferPrimary` 决定启动角色，不自动切换，接管必须人工发起（主机不在线时须勾选强制）。网络恢复后若出现双主，任期低者降级，任期相同按节点名决定。没有仲裁的两节点方案无法区分“对端宕机”与“网络分区”，生产应配置仲裁。
- 正常停机时主机主动释放租约，备机无需等待过期即可接管。

角色变化通过 `INodeRole.Generation` 通知各模块：采集引擎重建工作线程，控制服务（含顺控、计算脚本写点）拒绝下发，计算任务、聚合、定时报表、报警通知发件箱、定时备份均跳过。网关接入收件箱按角色拒绝上传。

## 切换

| 方式 | 发起位置 | 过程 |
|---|---|---|
| 自动 | — | 主机失联且仲裁租约过期 → 备机接管，事件记“自动接管” |
| 手动切换 | 主机“运维与高可用”页面，或 `POST /api/ha/switchover {reason}` | 主机停止采集与控制 → 在租约中写入交接对象 → 备机最终同步（全部历史 + 最新配置）→ 备机接管；任一步失败恢复原主机 |
| 人工接管 | 备机页面，或 `POST /api/ha/promote {reason, force}` | 主机在线时转交主机执行上一行；主机不在线时须仲裁确认租约已过期；无仲裁时必须 `force=true`（确认原主机已停机） |

切换接口要求全局“系统”权限，原因必填；成功与失败均写操作日志，并在本节点 `ha-events.ndjson` 记录（页面“事件”表）。

## 复制（应用层）

**Litestream 评估**：Litestream 按 WAL 帧把 SQLite 持续复制到对象存储，单库 RPO 可到秒级。不采用的原因：不支持 Windows 服务器；需要独占 checkpoint，与本系统运行中迁移、按月分库（`raw_yyyyMM.db`/`agg_*.db` 动态新建）冲突；恢复是“从副本重建文件”，不适合热备节点持续可读。因此实现了应用层复制：

- **配置库**：主机用 SQLite 在线备份生成一致快照并按 SHA256 去重；备机每 `ConfigSyncMs`（默认 5 秒）比较摘要，变化时下载、校验，用在线备份写回本地库，执行迁移并重载配置。用户、权限、报警记录、发件箱、控制策略、画面等随配置库复制。
- **历史库**：按文件、按 rowid 增量拉取（`HistoryBatchRows` 每批），原始表冲突忽略、聚合表覆盖；游标存于本节点 `StateDir/ha-node.json`，不随复制被覆盖。
- 复制只在本机为备机时运行，与接管互斥。

**RPO/RTO 与限制**

- 自动切换 RTO ≈ `LeaseMs + ClockSkewMs + HeartbeatMs`（默认约 8 秒）加采集重连时间；网关在此期间本地缓存，切换后补传。
- 非计划切换的 RPO：配置最多 `ConfigSyncMs`，历史最多 `HistorySyncMs` 加主机尚未入库的历史暂存（暂存目录不复制）。直连设备的采集在切换窗口内丢失；网关采集不丢（网关序号接续，中心对每条流接受一次序号跳变并审计“数据序号接续”）。
- 发件箱按快照复制，非计划切换后可能重发主机已发出的最后几条通知。
- 配置快照为整库传送，配置库很大（数十 MB 以上）时应调大 `ConfigSyncMs`。
- **Data Protection 密钥不复制**：安装备机时把主机 `keys/` 目录拷到备机相同位置（同一服务账户；Windows DPAPI 绑定机器时需改用证书保护密钥），否则备机接管后无法解密设备与网关凭据。

## 网关

网关配置 `GatewayAgent:FailoverServerUrls`（主机之外的其他中心地址）。连接失败或收到 503（备机）时轮换到下一个地址；握手允许中心已确认序号小于本地（新主机复制略滞后时），从中心确认点重发。

## 配置示例

两节点除 `NodeId`、`SelfUrl`、`PeerUrl` 外完全相同，`Jwt:Key` 与 `Ha:SharedKey` 必须一致（登录令牌在两节点通用）：

```json
"Ha": {
  "Enabled": true, "NodeId": "node-a",
  "SelfUrl": "http://10.0.0.11:5080/", "PeerUrl": "http://10.0.0.12:5080/",
  "SharedKey": "<至少 32 字符随机串>", "WitnessPath": "\\\\witness\\scada-lease",
  "AutoFailover": true, "PreferPrimary": true,
  "HeartbeatMs": 1000, "LeaseMs": 6000, "ClockSkewMs": 1000
}
```

首次部署：先单机部署主机并完成组态；备机安装同版本，拷入 `keys/`，以空配置库启动，几秒后完成首次全量复制。客户端访问建议在前面放负载均衡/VIP，以 `GET /api/ha/role`（匿名，返回 `role`）或 `/metrics` 中 `scada_ha_primary` 做健康检查；备机页面顶部显示“备机（只读）”及主机地址。

## 监控与验证

`/health` 中 `ha` 对象及告警 `ha_peer_down`、`ha_witness_unreachable`、`ha_replication_failed`、`ha_replication_stalled`、`ha_no_primary`；Prometheus `scada_ha_*`（见 `operations.md`）。集成测试 `HaClusterTests` 在本机启动两个真实服务进程，覆盖：初始角色与租约、配置与历史复制、备机拒绝网关与写请求、手动切换（审计）、主机被杀后自动接管、原主机重启后作为备机加入。
