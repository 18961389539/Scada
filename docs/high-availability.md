# 主备高可用

本文说明双机部署时密钥、报警、在途控制和历史数据如何对齐。产品默认（Timescale、AD/OIDC、强制 HTTPS、采集冗余等）不在此变更。

## 密钥环与 PKI

设备口令和通知凭据使用 ASP.NET Data Protection，密钥环在配置库同目录的 `keys/`（含报表签名证书 `keys/report-signing.pfx`）。OPC UA 证书在 `opc-pki`。

- **单机（未启用 `Ha`）**：Windows 仍可用本机 DPAPI 保护密钥环。
- **启用 HA 之后**：两台节点必须能打开同一套密钥环。Windows 双机不再使用本机 DPAPI，否则接管后解密设备口令和通知凭据会失败。改为使用 `keys/ha-dataprotection.pfx`（口令来自 `Ha:SharedKey`）保护新密钥，或把密钥目录放在两台都能访问且受 ACL 限制的位置。若目录里仍有本机 DPAPI 加密的旧密钥，启动时会尝试解包为可在两机读取的主密钥 XML，而不是在线改密产品。
- **日常复制**仍然只快照 `config.db`。密钥环和 OPC PKI 通过已认证的对等通道同步：`GET /api/ha/peer/secrets`，请求头 `X-Scada-Ha-Key`（`Ha:SharedKey`）。该通道只做认证，**不加密 HTTP**；共享密钥一旦泄露，攻击者可以拉取密钥环。生产环境应为对等连接启用 HTTPS，并限制 `keys/` 与 `opc-pki` 的落盘权限。不要在未认证通道上传密钥。不引入外部 KMS。
- 进程会用已有密文或哨兵做一次解密自检，失败时写入健康告警 `ha_keyring_unprotect`。完整备份仍会打进 `keys/` 与 `opc-pki`。

## 报警引擎

节点按设计先以备机启动。备机跳过报警判定和棚期到期写库，只排空总线，避免在运行库尚未追平时插入重复活动报警或改写棚期。提升为主机并完成一次运行库对齐后，会再次恢复活动报警并重载暂挂。若某规则已有未结束事件，Raise 会复用该事件，不再插入一条。判定仍然只在 `AlarmEngine` 做一份；备机不做完整判定。洪水抑制本来就不跨重启保留。

## 在途控制作业

备机启动时，不对从主机复制来的本机控制命令账本、顺控（`ControlSequenceRuns`）或配方下发（`RecipeDownloads`）做崩溃收口。这些写不会回到主机，若过早把仍在执行的作业标成失败或未知，接管后会被当成事实。

提升为主机并完成一次运行库追平后，再按「对端已死、结果未知、不自动重发或续跑」收口。健康页的接管核对列表会列出这些未知命令和中断的顺控、配方，便于核对现场后再用新命令号执行。人工切换若对端仍在跑，应先走现有最终同步，再决定是否收口。

## 运行库复制落后

运行库仍按 `HaRuntimeChange` 游标增量拉取，日常预算约 2 秒，强制切换约 20 秒。`LastRuntimeSyncTs` 只在本轮真正追平，或完成整库重置后更新。落后行数达到 1 万或连续 3 轮未能追平时，健康告警 `ha_runtime_behind`，指标 `scada_ha_runtime_rows_behind` 可见。接管时会记录未同步的运行库尾段（行数和涉及表）。落后行数不会阻止对端已死时的接管。这些阈值是实现常数，不是产品配置项。

## 历史暂存与缺口日志

`_spool/` 和 `history-loss.jsonl` 默认只在本机。强制/最终同步可拷贝对端暂存，新主机按现有幂等逻辑回放入库；同时合并对端缺口日志（重叠窗口去重）。若最终同步未能导入暂存，接管会把未回放暂存的时间窗和大约条数写入 `HistoryLossLog`。主机暂存较大而备机看不见时，健康提示 `ha_spool_unreplicated`。暂存不是第二套历史库，不会做持续双写。缺口队列溢出时，没有时间戳的窗口仍可能退回冲洗周期。

## 完整备份中的报表归档

完整备份会按保留期打包尚未清理的 `ReportsRoot`（默认 `data/reports`）。库内改存相对路径，还原时按新的归档根重写，并校验 SHA-256；文件缺失或哈希不符会明确失败，不会把记录标成已清理，也不重签旧文件。签名证书仍在 `keys/`。不提供在线一键恢复 HTTP 接口。操作步骤见 [publishing.md](publishing.md)。

工厂日历等厂级运营组态随配置库复制；站点文件中的部署项（JWT、`Ha:SharedKey`、监听地址）不进配置复制。详见 [configuration-planes.md](configuration-planes.md)。
