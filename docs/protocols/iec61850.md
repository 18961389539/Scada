# IEC 61850 MMS：决策与适配接口（未内置客户端）

协议值 `Iec61850`，默认端口 102。

## 决策

**本期不内置 IEC 61850 MMS 客户端，只提供适配接口、配置校验与映射逻辑。**

1. **许可**：主流开源实现 libiec61850（MZ Automation）为 **GPLv3 / 商业双许可**（已核实）。以库形式链接或 P/Invoke 调用均会使产品受 GPLv3 约束，因此不引入，也未参考其源码。
2. **自研可行性评估**：最小可用的 MMS 客户端需要 ISO 8073 COTP over TPKT（RFC 1006）、ISO 8327 会话、ISO 8823 表示层、ACSE 关联、MMS（ISO 9506）ASN.1 BER 编解码（Initiate、Read、Write、GetNameList、GetVariableAccessAttributes），控制还需 IEC 61850-8-1 的 SBOw/Oper/Cancel、增强安全的 CommandTermination，报告需 RCB 配置与 InformationReport 解析。没有许可可用的测试服务器（libiec61850 服务器同样为 GPL），无法做可信的互操作测试。以本期篇幅实现会得到一个未经验证、风险很高的控制通道，因此**不做**。
3. **当前交付**：
   - `Iec61850Spec`：引用语法 `LD/LN.FC.DO[.DA…]` 校验（FC：ST/MX/SP/SV/CF/DC/SG/SE/SR/OR/BL/EX/CO）；只有 CO 与 SP/SE/CF/DC 可写，CO 必须可写。可以先完成设备与测点配置、导入导出工程包。
   - `IIec61850Client` 适配接口与 `Iec61850Driver`：品质（validity/test/operatorBlocked/substituted）与时间戳映射、Bool 归一、读写经控制闭环；用假客户端测试。
   - 未注册实现时，连接报告：“IEC 61850 MMS 客户端尚未提供实现：libiec61850 为 GPLv3 许可不能内置……”，采集引擎按退避重试，诊断页可见。

## 需要用户决定的选项

| 选项 | 说明 |
|------|------|
| A. 购买 libiec61850 商业许可 | 最成熟；以 `IIec61850Client` 包装其 .NET 绑定即可接入。 |
| B. 其他商业 SDK（如 SISCO、Triangle MicroWorks） | 同样通过适配接口接入。 |
| C. 外部网关转换 | 61850 → OPC UA / IEC 104 / Modbus 网关，用本系统现有驱动接入（零开发）。 |
| D. 立项自研 | 需要真实 IED 或有许可的测试服务器做互操作测试，估计数周工作量。 |

## 适配接口约定

- `ConnectAsync(host, port, timeoutMs)`：建立 MMS 关联。
- `ReadAsync(references)`：按顺序返回 `Iec61850Sample(Value, Quality, TimestampMs, Error)`；`Quality` 低 2 位为 validity 枚举（0 good、1 invalid、2 reserved、3 questionable），bit10 substituted、bit11 test、bit12 operatorBlocked；`TimestampMs` 为数据对象 `t` 的 Unix 毫秒。
- `WriteAsync(reference, value)`：CO 按设备控制模型执行（direct / SBO / SBOw，增强安全须等待 CommandTermination），其他 FC 写属性；未确认必须抛出异常，驱动不重发。
- 读失败抛异常时驱动断开并由引擎重连。

## 品质映射

| 61850 | 本系统 |
|-------|--------|
| validity=good | Good（test/operatorBlocked/substituted 置位时为 Uncertain） |
| validity=questionable | Uncertain |
| validity=invalid / reserved | Bad |
